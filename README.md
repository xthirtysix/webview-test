# TV Code WebView

Статическая страница на HTML, CSS и JavaScript без фреймворков. Ввод четырёх цифр с экранной клавиатуры или пульта, навигация стрелками и OK, возврат кода родительскому Smart TV приложению через `postMessage`. Backend не нужен.

## Запуск и проверка

Для инструментов разработки нужен Node.js 22+; на телевизор загружаются только HTML, CSS и ES5 JavaScript.

```sh
npm ci
npm start
```

Открыть <http://localhost:4173/> — сразу появится экран ввода PIN. Эту же страницу другое приложение открывает в своём iframe/WebView. В отдельной вкладке ввод работает, но отправка кода требует соединения с родительским приложением.

```sh
npm test
npm run build
```

Сборка копирует экран и адаптер подключения в `dist/`, создаёт `.nojekyll`. Промежуточной страницы и кнопки открытия нет. Единственная dev-зависимость — Acorn для проверки синтаксиса ES5. Тесты проверяют ввод, навигацию и обмен сообщениями с родителем.

Для локальной проверки готовой сборки:

```sh
SERVE_DIST=1 npm start
```

## GitHub Pages

1. Загрузить проект в GitHub, основная ветка — `main`.
   Добавить в репозиторий `package.json` и `package-lock.json`: workflow использует `npm ci` и кеш npm. Если lock-файл отсутствует, используется `npm install` без кеша.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Push в `main` или ручной запуск на ветке `main` workflow **GitHub Pages** выполняет тесты, сборку и публикацию. Pull request выполняет только проверки и сборку.

Адрес экрана: `https://<owner>.github.io/<repository>/`. Все пути относительные, поэтому отдельная настройка `base` не нужна. Схема workflow соответствует [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Реальный URL появится после публикации в вашем репозитории; эта рабочая папка сама по себе ничего не публикует.

## Подключение к ../v3.22

В соседнем проекте уже есть окно iframe в `src/pages/profile/ui/p-profile-help/p-profile-help.vue` с `WEBVIEW_URL = 'https://example.com/'`. Этот проект его не меняет.

В будущем потребуется:

1. Указать опубликованный URL в `WEBVIEW_URL`. Разрешить его HTTPS origin в CSP / сетевых разрешениях пакетов Tizen, webOS и VIDAA, если такие ограничения включены. Проверить TLS на целевых старых ТВ.
2. Подключить `core.js`, `bridge.js`, `host.js` в родительский пакет; они экспортируют `window.TVCodeCore`, `window.TVCodeMessaging`, `window.TVCodeHost`. Они также могут выполняться как side-effect imports сборщика. Для TypeScript адаптировать API в типизированный модуль или добавить декларации глобальных объектов.
3. Создать `TVCodeHost` **до назначения `iframe.src`**, чтобы обработчик не пропустил `load`. После создания адаптера назначить URL экрана в `iframe.src`.

```js
var host = window.TVCodeHost.createHost({
  frame: iframeElement,
  origin: 'https://<owner>.github.io', // Только origin, без пути репозитория
  sessionId: createUniqueSessionId(), // Новая строка для каждого открытия
  onCode: function (code) {
    // code — строка, например "0012". Адаптер уже отправил ack.
    showReceivedCode(code);
    // Дать iframe обработать ack перед удалением, чтобы отобразилось подтверждение.
    window.setTimeout(closeWebview, 600);
  },
  onCancel: closeWebview,
  onError: showWebviewError
});
iframeElement.src = WEBVIEW_URL;
// При закрытии / размонтировании вызвать host.destroy(), затем удалить iframe.
```

`createUniqueSessionId`, `showReceivedCode`, `closeWebview`, `showWebviewError` в этом фрагменте — функции будущей интеграции. Их реализует родительское приложение. При закрытии отменить отложенный вызов `closeWebview`.

4. Сохранить существующий отдельный контекст `newFocusStore.initContext(...)`, закрытие через `deinitContext(...)` и возврат фокуса на кнопку открытия. `host.js` перехватывает распознанные клавиши на `window` в capture-фазе и останавливает дальнейшую обработку, чтобы фокус-движок родителя не выполнял те же действия. До `ready` ввод блокируется, Back продолжает закрывать окно.
5. Держать DOM-фокус в родителе при открытии. При клике по содержимому iframe приложение само обрабатывает локальные клавиши. Не добавлять вторую пересылку клавиш поверх `host.js`.
6. Весь жизненный цикл адаптера ограничить открытым окном, вызвать `destroy()` при закрытии и размонтировании, отменить таймер отложенного закрытия. На ошибке загрузки закрыть окно и вернуть управление родителю; отсутствие `ready` определяется через 10 секунд.

Родительский адаптер перехватывает Back `8`, `27`, `461`, `10009`. При необходимости зарегистрировать цифровые клавиши через платформенное API **в родительском приложении**, а не в iframe GitHub Pages. Стрелки, Enter и Back на Tizen не требуют регистрации.

### Packaged-приложения с origin null

Если родитель загружен из локального пакета и его `MessageEvent.origin` равен `"null"`, добавить к URL iframe `?allowOpaqueParent=1`. По умолчанию такие родители отклоняются.

Только ответ такому родителю использует `targetOrigin: '*'`; iframe проверяет `event.source === window.parent`, затем фиксирует origin и сессию первого `init`. Родитель всегда отправляет сообщения на точный HTTPS origin iframe и проверяет source, origin, сессию и формат ответа. Сессия связывает обмен с конкретным открытием, но не заменяет аутентификацию или серверную проверку кода.

## Протокол v1

Каждое сообщение — объект `{ channel: 'tv-code', version: 1, type: '...', sessionId: '...' }`. Session ID — непустая строка до 200 символов.

| Направление | type | Дополнительные поля |
| --- | --- | --- |
| Родитель → iframe | `init` | — |
| iframe → родитель | `ready` | — |
| Родитель → iframe | `key` | `keyCode`: целое число, `repeat`: boolean |
| iframe → родитель | `submit` | `code`: строка ровно из четырёх ASCII цифр |
| Родитель → iframe | `ack` | — |
| iframe → родитель | `cancel` | — |

При отправке форма блокируется. Если за 3 секунды не пришёл `ack`, форма снова доступна, фокус возвращается на «Отправить». Родитель подтверждает повторы, но вызывает `onCode` только один раз за загрузку iframe. После успешного `ack` iframe показывает подтверждение до закрытия родителем.

После успешного `ack` страница iframe также один раз отправляет родителю отдельное сообщение с введённым PIN (ведущие нули сохраняются):

```js
window.parent.postMessage(
  { type: 'success', pin: '0123' },
  'https://домен-приложения'
);
```

`pin` содержит фактически отправленный код, а целевой origin берётся из проверенного сообщения `init` родителя. Для явно разрешённого packaged-родителя с origin `null` используется `'*'`. При таймауте сообщение `success` не отправляется.

## Управление и совместимость

- Стрелки перемещают фокус без перехода через края; OK нажимает кнопку. Внизу сетки переход вниз ведёт на отправку только при полном коде; переход вверх с отправки ведёт на `0`.
- Кнопки «Удалить» и «Очистить» исправляют код. Цифры пульта и клавиатуры вводятся напрямую. Пятый символ игнорируется, ведущие нули сохраняются.
- Начальный фокус на `1`; после четвёртой цифры фокус не переносится автоматически. Поле readonly не открывает системную клавиатуру ТВ.
- На компьютере Backspace удаляет цифру, Escape запрашивает закрытие. На VIDAA/Hisense локальный `8` определяется как Back по user-agent; родительский адаптер всегда считает `8` кнопкой Back. В сомнительных случаях использовать родительскую пересылку.
- Для старых движков используются ES5, обычные `<script>`, простая CSS-раскладка без Grid и CSS-переменных. Системные шрифты, без CDN и SDK. Это не гарантирует работоспособность на каждой исторической версии ОС.

Перед фиксацией минимальных версий проверить на реальных webOS, Tizen, VIDAA: загрузку GitHub Pages по HTTPS, начальный фокус, все направления, удержание OK/цифр, код `0000`, удаление, отмену, получение и подтверждение кода, повторное открытие и читаемость в 720p/1080p. Проверить и hosted-, и packaged-режимы приложения. Прямой запуск по `file://` не заменяет HTTP(S) проверку.

Справочные документы: [LG Magic Remote](https://webostv.developer.lge.com/develop/guides/magic-remote), [Samsung Remote Control](https://developer.samsung.com/smarttv/develop/guides/user-interaction/remote-control.html), [Web Messaging](https://html.spec.whatwg.org/dev/web-messaging.html).
